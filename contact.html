Frequently Asked Support Questions

Why did a PDF fail to process or crash the browser tab?
Because ZeroUpload processes documents locally inside your browser's RAM, very large files (such as 500+ page scans or files exceeding 100MB) can occasionally reach browser memory limits on mobile devices or computers with low available RAM. To resolve this, close background browser tabs, ensure your browser is updated to the latest version, or use the "Split PDF" tool first to process the document in smaller sections.
Can ZeroUpload recover my modified document if I accidentally closed the tab?
No. Because ZeroUpload is 100% private, no document data or state is ever sent to or stored on our servers. As soon as you refresh or close the tab, the in-memory document buffer is permanently destroyed. Always make sure to download your completed file before closing the window.
How can I report a security vulnerability?
We take security disclosures with extreme urgency. Please email full technical reproduction details to support@zeroupload.co with the subject line "[SECURITY DISCLOSURE]". We acknowledge reports within 6 hours.
Is there an API or command-line version of ZeroUpload?
Currently ZeroUpload is built for direct in-browser consumer and professional productivity. For high-volume automated batch processing, we recommend checking out the open-source libraries we build upon: pdf-lib and Mozilla pdf.js.
